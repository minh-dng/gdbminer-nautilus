# CONTEXT.md

Domain vocabulary for the GDBMiner ↔ NAUTILUS integration. Prefer these terms
in issues, PRs, ADRs, and code.

## Glossary

| Term | Definition | Avoid |
| ---- | ---------- | ----- |
| **GDBMiner grammar** | Fuzzing Book-style mapping in `parsing_g.json`: `{"[start]", "[grammar]", ...}` where nonterminals look like `<name>` and alternatives are token lists. | "the JSON", "miner output" (too vague) |
| **NAUTILUS grammar** | NAUTILUS-native production list: `[nonterminal, rhs]` pairs, root `START`, or the equivalent Python `ctx.rule` / `ctx.script` / `ctx.regex` script. | "the fuzzer grammar" without saying which side |
| **Adapter** | Parent-repo module that converts a GDBMiner grammar into a NAUTILUS grammar and owns symbol mapping, terminal expansion, and validation. | "converter script" when speaking of the package |
| **Symbol map** | Deterministic mapping from GDBMiner nonterminal names to NAUTILUS-legal names; required because GDBMiner uses `<...>` and NAUTILUS expects `[A-Z]...`. | "rename table" |
| **Campaign** | One configured NAUTILUS (and optional AFL++) run against a target binary, with a fixed grammar, workdir, and time budget. | "job", "run" (too ambiguous) |
| **Preflight** | Checks that Python, Cargo, submodule pins, and instrumented targets exist before conversion or campaign start. | "setup check" |
| **Contract test** | Parent-repo test at the adapter seam: GDBMiner JSON in → NAUTILUS grammar out (and optionally generated bytes). | unit test of either submodule |
| **Evaluation artifacts** | Generated traces, corpora, `evaluation/` trees, and experiment outputs. Never committed here; gdbminer sparse-checkout excludes them. | "results" when meaning source |

## Seams

The highest useful seam is the **adapter API**: load GDBMiner grammar →
emit NAUTILUS grammar (+ symbol map). Campaign orchestration sits above that
seam; submodule internals sit below it.
